Процесс

AI встраивается в поток, а не живёт отдельно

Классификация, память, сообщения и действия работают внутри бизнес-сценария.

Контроль

Интеграции не расползаются по ручным костылям

CRM, webhooks, очереди и уведомления держатся в читаемой архитектуре.

Про направление

Собираю решения от архитектуры до запуска: AI-агенты, Telegram-боты и backend-сервисы, которые работают внутри реальных процессов, а не живут отдельно от бизнеса.

Практический фокус

Приоритет у скорости запуска, понятной эксплуатации и пользы для команды.

Нормальная архитектура

Стек подбирается под сценарий, нагрузку и будущие изменения, без лишней сложности.

Спокойное сопровождение

Логи, очереди, исключения и интеграции остаются видимыми и читаемыми после релиза.

Как собираю решения

Сначала карта сценариев и ограничений, потом выбор фреймворков и сервисов. Стек подстраивается под задачу, а не наоборот.

Внутри рабочего контура

  • Определяю точки входа: формы, чат, CRM, внешние API, админские сценарии.
  • Разделяю роли: интерфейс, backend, AI-слой, база, очереди, уведомления.
  • Сразу предусматриваю хранение состояния, retries, fallback-ветки и логирование.
  • Оставляю понятный путь для роста после MVP: новые сценарии, роли и интеграции.

advokat.rag

AI + Telegram

Юридический ИИ-консультант

Telegram-бот превращает бытовое описание ситуации в предварительную квалификацию по УК РФ. Связка «извлечение фактов → поиск статей → LLM → проверка вывода» крутится полностью локально на Ollama, без внешних API. Бот задаёт уточняющие вопросы и пересматривает вывод по ходу диалога, а не выдаёт один статичный ответ. Легко переносится на любую другую базу документов — не только на УК РФ.

  • Ollama, локально
  • RAG по кодексу
  • Telegram

saloon.assistants

3 ассистента в одном

Нейроассистенты для автосалона

Одно локальное приложение с тремя разными ассистентами — продажи, подбор персонала и сервис — у каждого своя база знаний и промпт. Telegram HR-бот

HR-бот с голосом и фото

Бот для общения с кандидатами в Telegram, который принципиально не выдумывает ответы — отвечает только по документам и страницам сайта, которые сам же проиндексировал. Понимает голосовые сообщения и фотографии, умеет ответить голосом и сгенерировать иллюстрацию по запросу. Базу знаний пополняет на лету: скидываешь боту PDF, DOCX или ссылку на сайт компании — он сам всё разбирает и переиндексирует. Хорошая основа для любого клиентского бота, где важнее не соврать, чем казаться умным.

  • Голос + Vision
  • Автопарсинг сайта
  • RAG без галлюцинаций

polati.hr

Production HR-система

HR-ассистент для стройкомпании

Готовое production-решение для реальной компании: HR-ассистент отвечает кандидатам по вакансиям сразу в двух каналах — на сайте и в Telegram — с единой логикой и общей памятью диалога. По ходу разговора бот сам, по одному полю, заполняет анкету кандидата и сохраняет карточку, без отдельной формы. По описанию автора, такая автоматизация типовых вопросов снимает до 70–80% нагрузки с рекрутёров и сокращает время первого ответа, работая 24/7. Промпт и база знаний обновляются на лету, без перезапуска сервера.

  • Web + Telegram
  • FAISS + GigaChat
  • Анкета автоматом

shaman.audit

Аудио/видео анализ

Шаман — разбор любого разговора

Telegram-бот принимает видео, аудио, голосовое или просто ссылку на ролик, расшифровывает через AssemblyAI и прогоняет текст через собственный аналитический промпт. Вместо пересказа бот восстанавливает реальную картину происходящего — связи, интересы, скрытые зависимости, точки напряжения — и только потом даёт прогноз развития, честно помечая недостающую информацию, а не додумывая её. Все разборы сохраняются в PostgreSQL, так что по ним можно строить историю. Применимо к разбору переговоров, звонков продаж, интервью — везде, где нужен не пересказ, а трезвый анализ происходящего.

  • AssemblyAI
  • Анализ + прогноз
  • PostgreSQL

Веб-дашборд

Live-дашборд топ-10 крипты

Личный дашборд топ-10 криптовалют: цена, суточное изменение и капитализация обновляются каждые 30 секунд без перезагрузки страницы. Есть регистрация и вход с хешированием паролей — у каждого пользователя свой личный кабинет, а не общий экран на всех. Данные кешируются на сервере, чтобы не упираться в лимиты бесплатного API CoinGecko, а при сбое сети отдаётся последнее известное значение вместо ошибки. Шаблон, который легко адаптировать под дашборд любых живых данных — курсы валют, показатели маркетплейса, метрики продукта.

  • CoinGecko API
  • Auto-refresh 30s
  • Auth + кеш

Backend-шаблон

Минимальный AI-агент на FastAPI

Минимальный production-ready каркас: FastAPI-сервис с одним эндпоинтом /chat, который проксирует запросы в Groq на модели Llama 3.3 70B — одном из самых быстрых доступных инференсов. Ни лишних зависимостей, ни лишней логики — только то, что нужно, чтобы за несколько минут поднять быстрого AI-агента и подключить любой фронтенд. Уже настроены CORS и Procfile для деплоя на Heroku/Railway. Хорошая стартовая точка, если нужен не готовый продукт, а чистый фундамент под свою логику агента.

  • Groq · Llama 3.3
  • FastAPI
  • Готов к деплою

ultrashop.exe

Desktop, C++ / Qt6

Витрина магазина из папки с фото

Десктопное приложение на C++/Qt6: кладёшь в папку фотографии товаров, названные по схеме «бренд_модель», и приложение само собирает из них витрину с ценами и карточками в тёмном glassmorphism-интерфейсе. Цену ищет по названию файла в открытых источниках, а если сети нет — считает её детерминированно из хеша названия, так что цена не скачет от запуска к запуску. Кнопка «Publish Showcase» поднимает витрину как веб-страницу в локальной сети — коллеги открывают её на телефоне без единой настройки. Показывает, что стек не ограничен Python и веб-бэкендом — под задачу можно собрать нативное десктоп-приложение с нуля.

  • C++ / Qt6
  • Авто-цены по имени файла
  • Публикация в LAN

Компетенции

Закрываю задачу не отдельным модулем, а целиком: от анализа входных условий до запуска и развития продукта.

Что беру на себя

  • Архитектуру backend- и AI-решения под реальный сценарий.
  • Telegram-ботов, формы, меню, админские ветки и чат-интерфейсы.
  • AI-агентов, классификацию, извлечение данных, prompt engineering и routing.
  • Интеграции с CRM, оплатой, Google Sheets, CMS, ERP и внешними API.

Что получает проект

  • Понятную структуру: интерфейс, backend, AI-слой, БД, очереди и интеграции.
  • Сценарии с контролем состояний, ошибок, логов и повторных попыток.
  • MVP, который можно расширять, а не переписывать после первого запуска.
  • Продукт, встроенный в процесс команды, а не висящий отдельной витриной.

Результат: продукт остаётся понятным после запуска и не превращается в набор несвязанных интеграций и ручных костылей.
